Features

Continuity, not just retrieval

Every memory tool can find a fact. Logos makes sure the next agent gets the right one.

Consolidation

Old values are withheld, not ranked lower

When a fact changes, the stale one stops coming back, and why it was superseded goes on the record.

logos memory log
Handoff

Dead ends travel between agents

A checkpoint carries what was verified, what failed and what is next.

/handoff · resume
Cold start

Useful before you teach it anything

Reads your git history and proposes what it can defend, each with the command behind it.

logos bootstrap --dry-run
Ownership

Markdown you can grep and commit

The vault is truth; the SQLite index is a cache. Delete it and it rebuilds from the files.

Benchmark

Don’t take my numbers for it

I wrote the benchmark and the system that wins it. It runs on your machine in one command, so check it yourself first.

$ go run ./cmd/logos bench continuity --logos-only

Install

Pick how you work

Every route installs the same single binary and points every agent at the same vault.

macOS and Linux. The formula is logos-mcp, because Homebrew already has a logos; the command it installs is still logos.

  1. $ brew install coder8124/tap/logos-mcp
  2. $ logos setup

Update with brew upgrade logos-mcp, not logos update — hosts are wired to brew’s opt path, which survives the upgrade.

Windows, or anywhere without Homebrew. Needs only Node. --dry-run prints the plan and exits.

$ npx -y @noeton/logos setup

The version to prefer in Claude Code: besides the MCP server it installs a SessionStart hook that puts the last handoff in front of the model before it does anything.

  1. / plugin marketplace add Coder8124/logos
  2. / plugin install logos@logos

Deep links that hand the host a finished config. Nothing else to edit.

Add to Cursor Add to VS Code

Zed, Cline, Windsurf, Continue, Gemini CLI or your own agent. npx resolves the binary on demand, so the config is portable between machines.

{
  "mcpServers": {
    "logos": {
      "command": "npx",
      "args": ["-y", "@noeton/logos", "mcp", "serve"]
    }
  }

Add "env": { "LOGOS_VAULT": "/path/to/vault" } to keep the vault somewhere other than ~/logos.

One static executable, pure Go with CGO_ENABLED=0, so a single Linux build covers glibc and musl alike.

Private by design

What installing does to your machine

  • A directory of markdownAt ~/logos unless you say otherwise. Open it, grep it, commit it, delete it.
  • Nothing wired without a yesSetup lists the agents it found and what it would write to each before touching anything.
  • Agents propose, you acceptA memory written over MCP waits in a review queue — logos review accepts or rejects it.
  • No account, server or telemetryNothing leaves the machine. .logos/index.db is a cache that rebuilds from the files.
  • No AI runtime requiredCheckpoint, resume and dead ends are markdown and SQL. A 274 MB model adds semantic recall if you want it.
  • No postinstall scriptThe binary ships as real package contents, so --ignore-scripts and offline installs work.
